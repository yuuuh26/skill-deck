# Skill Deck v1.1.0

複数AIで使う自作Skillを管理する個人用PWA。

- Skillの作成・検索・本文コピー、版ごとのAI対応状況と必要ツール
- 保存ごとに旧版を維持。過去版を元に新しい最新版を作成
- 編集中の本文Undo / Redo
- IndexedDBに先に保存し、変更後約1秒でクラウドへ自動送信
- 同じ復旧キーで接続したスマホ・パソコンへ、表示中3秒間隔で更新を確認
- クラウドの最新データはアプリによる期限なし。全データのバックアップは最新を含め3世代
- Skill単位の過去版は制限せず維持。JSON完全バックアップ、検証付き復元・統合、Markdown出力
- オフライン利用、通信復帰・再起動後の再送、永続ストレージ状態の確認

## 利用URLと最初の移行

クラウド版: https://skill-deck-cloud.dengana-10011212.workers.dev/

旧端末保存版: https://yuuuh26.github.io/skill-deck/

1. 旧アプリの設定で「全データをエクスポート」を押す。
2. クラウド版の設定でJSONをインポートし、件数と内容を確認する。
3. 設定で端末名とSkill Deck専用の復旧キーを入力して接続する。
4. 「クラウドと同期済み」を確認する。
5. パソコンでもクラウド版を開き、同じ復旧キーで接続する。空の新端末はクラウドの内容を自動取得する。

オリジンが変わるため旧IndexedDBは自動移動しません。元のデータは消さず、JSONを保管してください。既に両方にデータがある場合は内容と件数を確認し、どちらを使うか選択します。

## 同期・復元の動作

明示的なSkill保存、AI/ツールマスター追加、JSONインポート後に自動送信。検索・閲覧・入力途中はバックアップを作りません。同期はアプリを開いている間に実行され、閉じている端末は次回起動/再表示時に更新します。

編集中は他端末のデータを適用せず、保存後に変更の競合を確認します。両方が変更されている場合、クラウド全体の更新番号を照合して上書きを止め、設定で選択します。異なるSkillの編集でも安全のため競合になります。自動マージはしません。

端末データと送信待ち更新を同一IndexedDBトランザクションに保存。送信中の新しい編集を送信済みと扱わず、再送には同じ処理IDを使います。Web Locksで同一オリジンのタブを制御。サーバーは更新番号を比較し、完全な内容を再取得・検証した後、同一D1バッチ内で最新の確定と3世代の整理を行います。再送の処理済み記録は内容のハッシュと更新番号だけを保持します。

設定に「今すぐクラウド保存・同期」「履歴から復元」「復元前の退避データを書き出す」を用意。復元時は現端末データを内部に退避し、確認中の変更を再チェックします。履歴の復元は新しいクラウド版として送信されます。

## 認証と管理

アプリ別オリジン・D1・復旧キー・ホスト限定Secure/HttpOnly/SameSite=Strict Cookie。原文の復旧キーは端末DB・localStorage・JSON・Service Workerに保持しません。サーバーはキー検証ハッシュと端末通行証ハッシュのみ保存。復旧キーは256bit以上の乱数を使用し、秘密ファイルで非公開に保管します。

設定の接続・端末管理で、復旧キーをその都度入力して一覧・名前変更・個別解除・全端末解除・復旧キー変更ができます。キー変更は全端末を解除し、新しいキーをファイル出力します。一般の端末通行証だけでは管理できません。

APIは認証必須・Origin検証・認証試行制限・入力検証を実施。APIレスポンスはno-storeで、Service Workerは`/v1/`をキャッシュしません。CSPとtextContentによってSkill本文をHTMLとして実行しません。noindexはアクセス制限ではありません。端末通行証にはサーバー側期限を設けず、ブラウザのCookie保持制約による再接続はあり得ます。

## 開発・配備

`npm ci`、`npm test`、`npm run build`。`cloudflare/dist/site-worker.js`をCloudflare Workerとして配備し、専用D1を`DB`に、復旧キーのSHA-256をSecret `BACKUP_TOKEN_SHA256`に設定。`cloudflare/schema.sql`は新規専用DBへの非破壊初期化用。既存DBやキーを再作成しないでください。公開コードに原文キー・通行証・Cloudflare APIトークン・本人データを含めないこと。

クラウドの最大スナップショットは20 MiB。D1の行サイズ制限に合わせてJSONを600,000 UTF-16単位以下のチャンクへ分け、サロゲートペアを保持。公開フロントエンドはWorkerに埋め込み、配備後もGitHubがアクセス不能ならキャッシュからオフライン利用できます。

`tests/browser-check.mjs`は別々のスマホ/PCブラウザコンテキストで同期・オフライン再起動・競合・3世代を検証するローカル補助チェック。PlaywrightとChromiumがある環境で、`CODEX_PRIMARY_RUNTIME_NODE_MODULES`を設定して実行してください。
